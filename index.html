I build one scoring model, and I name where it stops working.

Mine ranked 30,000 pages by risk of losing search traffic. 3,388 had zero impressions the month before. A page on zero cannot fall. Those rows were answered by arithmetic, not by the model.

I found it in my own build. I had already published a number that rested on it.

What I do about that:

  • Hold out whole clients, then measure what it bought — 0.901 against a random split's 0.908.
  • Quote only numbers that reproduce from a clean clone.
  • Name the limits, with a fix beside each, in the repo.
  • Label every figure with the slice it came from.

What that discipline cost me

Removing those rows took the random forest's ROC AUC from 0.750 to 0.565. A coin flip is 0.500. Precision@50 came to 0.600 against a base rate of 0.611 — below the base rate. The 0.680 I had published is withdrawn. All of it is written up with the code that produced it.

Where the evidence is

  • Three cases — the leak, the split that was measured rather than assumed, and the feature set I refused to build on.
  • Seven named failure modes — each with a fix beside it, or an honest note that no fix is applied.
  • A scoped trial — one dataset, one ranking question, free at that size.
