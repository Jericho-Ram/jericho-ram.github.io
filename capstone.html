The stack, the site, and the agent

GENERAL AI FLUENCY CAPSTONE · WEEK 6

Three aspects with the link provided to the artifact with full information. Every number below reproduces from the repo it links to.

01 · The stack

The pipeline runs end to end from a phone — Colab for notebooks, Termux for git, the GitHub web editor for files. No laptop was involved in any of it.

What it produced, and what happened when I checked it: of the 30,000 rows in the bundled CSV, 3,388 had zero impressions in the prior 30 days and were labelled not-declining by arithmetic rather than by anything the model read. Scored on the 26,612 pages where decline was actually possible, the random forest's ROC AUC fell from 0.750 to 0.565 and Precision@50 from 0.740 to 0.600, against a base rate of 0.611. The Precision@50 of 0.680 I had already published is withdrawn.

02 · The site

Plain HTML, one shared stylesheet, GitHub Pages. Chosen over Jekyll and Astro because both need a build step I cannot run on a phone. The limit is named with a trigger rather than a feeling: when the same header needs editing in four places, it is time to switch.

  • The site itself — six pages, one style.css
  • DNS walkthrough — written before the subdomain exists, so it works as a checklist when it lands
  • Seven failure modes — each with a fix beside it, or a note that none is applied

03 · The agent

A claim auditor: it takes a number published on a page and traces it back to the file and line that produced it. I ran it against this site before submitting the spec that describes it, and the result changed the spec.

It found two things that looked wrong. Only one was. A grouped split reported as buying 0.008 subtracts to 0.007 from the two published figures — but at four decimals the split scored 0.9008 against 0.9085, a real gap of 0.0077. Every figure was correct; the page had rounded away the precision a reader needed to check it. The second was real: a chart caption claimed all 30,000 rows while the plotting call passed the filtered frame at 26,612.

  • The auditor spec — skills/auditing-published-claims/SKILL.md

What this doesn't show

The auditor has no trigger hook. It runs when I ask it, on the page I hand it, and the discrepancy that starts a run is one I noticed first — it supplies provenance, not suspicion. Its one unprompted flag was a false positive: it compared a date-filtered pull against an unfiltered one and reported the filter as a defect. That failure is written into the spec, because it is the same population error the model itself was built to catch.
